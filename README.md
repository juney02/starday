# 별하루 (BYEOLHARU)

오하아사 12별자리 운세 순위를 보여주는 모바일 웹앱입니다. 전체가 Google Apps Script(GAS)로 만들어져 있고, 데이터는 연결된 구글 시트에 저장됩니다.

**▶ 앱 열기: https://juney02.github.io/starday/** (링크가 있으면 로그인 없이 누구나 열 수 있어요 — 2026-10-17부터)

> 운세 내용은 ABC TV「おはよう朝日です」공식 사이트 자료이며, 이용 허락은 아직 확인하지 않았어요. 권리자의 요청이 있으면 내용 표시를 멈추고 공식 링크만 보여주도록 바꿉니다(관리자 화면 → 설정 → 이용 허락 상태 LINK_ONLY).

> 깃허브에는 코드만 있어요. 앱은 Google Apps Script에서 실행되고, 위 주소는 그 앱으로 이동시켜 주는 입구 페이지(`docs/index.html`)예요.

## 3. 자동 업데이트가 잘 되는지 확인하는 방법 (TEST 모드)

1. 관리자 화면 → **현황** 탭 → `자동 실행 트리거: 설치됨`, `자동 갱신: 켜짐` 확인
2. **지금 데이터 확인** 버튼 → 메시지에 `REVIEW`(승인 대기) 또는 `SUCCESS`가 나오면 수집 성공
3. **운세 데이터** 탭 → 12개 별자리 카드에서 일본어 원문과 한국어 번역 확인 → **공개**
4. 사용자 화면을 열어 둔 채 공개하면, 최대 1분 안에 화면이 저절로 바뀝니다. (새로고침 불필요)
5. **수신 기록** 탭에서 실행 기록 확인. 실패 상황은 **설정** 탭의 `테스트 시나리오`로 재현할 수 있어요 (순위 중복, 별자리 누락, 날짜 불일치, 이미지 게시물, 게시물 없음).
6. 내일 아침 8시 이후에 `수신 기록`에 `AUTO 08:00` 기록이 생겼는지 확인하세요. 이게 진짜 "자동 실행" 확인입니다.

## 4. 운영 모드로 전환하기 (공식 데이터)

**순서를 꼭 지켜 주세요. 권한이 확인되기 전에는 내용이 공개되지 않도록 설계돼 있습니다.**

1. [X 개발자 포털](https://developer.x.com)에서 앱을 만들고 **Bearer Token**을 발급받아 스크립트 속성 `X_BEARER_TOKEN`에 넣습니다.
   - ⚠️ X API는 플랜(무료/Basic/Pro 등)에 따라 *다른 계정 게시물 읽기 가능 여부*, *월 호출 한도*, *요금*이 다르고 자주 바뀝니다. 가입 전에 현재 플랜의 권한·가격·한도를 꼭 확인하세요. 권한이 없으면 수집은 `FORBIDDEN`으로 기록되고, 비공식 크롤링으로 우회하지 않습니다. (대신 관리자 화면의 **수동 입력 시작**으로 운영할 수 있어요.)
2. 관리자 화면 → 설정 → **동작 모드: PRODUCTION**
3. 이 단계에서는 이용 허락 상태가 `UNVERIFIED`라서 사용자에게는 **공식 게시물 링크만** 보입니다. (게시물 ID·링크·게시일 같은 출처 정보만 저장)
4. 오하아사(ABC TV) 쪽에서 *저장·번역·앱 내 표시·재배포* 허락을 받은 **뒤에만** 이용 허락 상태를 `APPROVED`로 바꿉니다. 계정이 공개되어 있다는 이유만으로는 재배포가 허용된 것이 아닙니다.
5. 번역을 쓰려면 `ANTHROPIC_API_KEY`를 넣습니다. 번역 결과는 관리자가 한 번 확인한 뒤 공개하는 것을 권장합니다. (`AUTO_PUBLISH`는 신뢰가 쌓인 뒤에 켜세요)

### ⚠️ 게시물 형식 확인이 필요해요
실제 @Hi_Ohaasa 게시물이 어떤 문장 형식(텍스트인지 이미지인지)으로 올라오는지는 아직 확인하지 못했습니다. 분석기(`Parser.gs`)는 `N位 별자리이름` 줄 + 설명 + `ラッキーアイテム：` 형식을 기준으로 만들었어요. 실제 게시물과 다르면 **잘못 공개되지 않고 검증 실패로 멈추니** 안전하지만, 그 경우 `parseHoroscopeText_` 함수를 실제 형식에 맞게 고쳐야 합니다.

## 4-1. 공식 사이트에서 실제 운세 가져오기 (기본 방식, 혼자 보는 용도)

공식 페이지(`asahi.co.jp/ohaasa/week/horoscope/`)는 빈 틀이고, 순위는 `https://www.asahi.co.jp/data/ohaasa2020/horoscope.json` 파일을 읽어 그립니다. 이 파일 하나를 하루 최대 4번(이미 받았으면 안 부름) 조회합니다. robots.txt는 이 경로를 막고 있지 않아요(점검으로 확인).

**실제 결과 보는 순서 (관리자 화면 → 설정 탭)**
1. 동작 모드 → **PRODUCTION**, 수집 경로 → **공식 사이트** (기본값)
2. 출처 이용 허락 상태 → **APPROVED** (혼자 보는 용도로 내용을 표시한다는 뜻으로 사용. 웹앱 접근은 "나만" 유지!)
3. (선택) "검증을 통과한 데이터를 자동 공개" 켜기
4. 현황 탭 → **지금 데이터 확인** → 운세 데이터 탭에서 확인 → **공개**
5. 번역: 기본은 Apps Script 내장 Google 번역(키 필요 없음, 품질은 보통). 더 자연스러운 번역을 원하면 `ANTHROPIC_API_KEY`를 넣으세요. 번역은 항목별로 수정할 수 있어요.

**동작 방식과 한계**
- 데이터의 방송일이 오늘이 아니면(주말·휴방일) 저장하지 않고 "아직 업데이트되지 않았어요"를 보여줍니다.
- 설명은 탭으로 구분된 문장들이고, 마지막 칸(앞에 빈 칸이 있을 때)을 행운 아이템/색으로 읽습니다. 색 단어 목록에 없으면 아이템으로 분류하니 틀리면 관리자 화면에서 고치세요.
- 사이트가 데이터 구조를 바꾸면 `FORMAT` 오류로 멈추고 잘못된 값을 공개하지 않습니다. 점검 함수(`SiteClient.gs`의 `inspectPublicData`)로 다시 구조를 확인할 수 있어요.
- 사이트가 접근을 막으면(403/429) 우회하지 않고 멈춥니다.
- 다른 사람에게 공개하기 전에는 ABC TV 허락을 받으세요.

## 4-2. AI 도우미 (Gemini 에이전트)

하단 메뉴의 **AI 도우미** 탭에서 질문하면, AI가 필요한 정보를 스스로 골라 가져와서 답해요. (에이전트 = 도구를 골라 쓰는 AI)

| 도구 | 하는 일 |
|---|---|
| 운세 조회 | 한 별자리의 하루 운세(순위·설명·행운 아이템) |
| 전체 순위 | 12별자리 순위 |
| 운세 기록 | 최근 며칠 순위와 평균·최고·최저 |
| 별자리 비교 | 두 별자리의 운세 나란히 보기 (궁합 점수는 공식 정보가 아니라서 주지 않음) |
| 앱 안내 | 알림·기록·개인정보 등 사용법 |

**켜는 방법**
1. [Google AI Studio](https://aistudio.google.com)에서 Gemini API 키를 발급해요.
2. Apps Script 편집기 → 프로젝트 설정 → 스크립트 속성에 `GEMINI_API_KEY`로 등록해요. (코드에 쓰지 마세요)
3. 편집기에서 `listGeminiModels`를 실행해 쓸 수 있는 모델 이름을 확인하고, 다르면 관리자 화면 → 설정에서 모델 이름을 바꿔요. (기본값 `gemini-3.1-flash-lite`는 확인하지 못한 이름이에요)
4. 관리자 화면 → 현황에서 `AI 도우미: 키 등록됨`, `AI 마지막 오류`를 확인해요.

**안전장치**
- 키는 서버에만 있고, 요청 주소가 아니라 헤더로 보내요. 화면·오류 메시지·관리자 응답에 나오지 않아요.
- AI에는 **내 별자리와 질문**만 보내요. 생년월일·출생시간은 보내지 않아요. 대화는 서버에 저장하지 않아요.
- 운세 순위·문구는 **저장된 데이터를 도구로 확인한 값만** 말하게 해요. 데이터가 없으면 "아직 없어요"라고 말하고, 테스트 데이터는 "가상"이라고 밝혀요.
- 조언·궁합 이야기는 "AI 의견(참고용)"으로 표시해요. 도구 결과 속 글은 명령이 아니라 데이터로만 취급해요.
- 질문 500자, 대화 10개, 도구 호출 5번, **하루 50회(전체 합계)** 로 제한해요. 한도·켜기/끄기는 관리자 화면에서 바꿔요.
- AI가 마크다운 기호를 섞어 보내도 서버와 화면에서 한 번씩 지워요. 답변 속 HTML은 실행되지 않아요.
- 마음이 많이 힘든 이야기에는 공감하고 전문 기관(자살예방상담전화 109)을 안내하도록 했어요.

## 5. 안전장치 요약

- 게시물이 없으면 운세를 만들지 않고, 이전 날짜 운세를 오늘 것으로 쓰지 않습니다.
- 12별자리·1~12위·중복 없음·작성자·날짜가 모두 맞아야 공개할 수 있습니다. 하나라도 틀리면 `검수 대기`로 저장됩니다.
- 오류가 나도 이미 저장된 데이터는 지워지거나 바뀌지 않습니다. 공개된 행과 관리자가 수정한 행은 자동 수집이 덮어쓰지 않습니다.
- X API 장애(5xx/네트워크)는 2초·4초 간격으로 최대 2번만 재시도하고, 한도 초과(429)와 인증 오류(401/403)는 재시도하지 않습니다.
- 같은 시각에 여러 번 실행돼도 `LockService`와 "슬롯 처리 기록"으로 중복 저장을 막습니다.
- 비밀 값(토큰·키)은 스크립트 속성에만 있고, 화면이나 관리자 응답에는 "등록됨/없음"만 표시됩니다.
- 관리자 기능은 모든 호출에서 서버가 토큰을 다시 검사하고, 10번 틀리면 10분간 잠깁니다. 인증을 설정하지 않으면 관리자 기능은 꺼져 있습니다.
- 운세 보관 기간(`RETENTION_DAYS`, 기본 30일)이 지난 기록은 매일 9시 최종 확인 뒤 삭제되고, 달력에서도 보이지 않습니다. 제한이 필요 없으면 0으로 두세요.

## 6. 시트(DB) 구조

`setupSheets`가 만드는 탭: `daily_horoscopes`, `import_logs`, `source_settings`, `source_posts`
- `daily_horoscopes`는 (날짜, 별자리, 데이터 모드) 조합이 중복되지 않게 저장합니다. TEST 데이터와 PRODUCTION 데이터는 `data_mode`로 분리돼요.
- `source_settings`의 `authorization_status`: `UNVERIFIED` → `LINK_ONLY` → `APPROVED`

## 7-1. 디자인 시스템 (5번 프로젝트에서 새로 정비)

- 디자인 값은 `src/Styles.html` 맨 위 **토큰**(색·글꼴·간격·모서리·그림자·모션)에서만 바꾸면 전체 화면에 반영돼요. 새 화면을 만들 때도 같은 부품(`.btn` `.card` `.tile` …)을 쓰세요.

- 자세한 진단·시스템·검증 결과: `디자인_진단과_시스템.md`, 전/후 비교: `디자인_비교/비교.html`
